# Stockroom 學習筆記

這是一個小型 Java 個人練習項目，沒有假設它是實際營運系統或已提交的課堂作業。題目是管理一個小商店或文具櫃的庫存。

## 先跑一次

1. 安裝 JDK 21 或以上版本。
2. 在項目目錄執行 `sh ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo`。
3. 在瀏覽器開啟 `http://localhost:8080`。
4. 找一個商品，記錄入庫，再記錄出庫。
5. 嘗試出庫超過現有數量，觀察錯誤訊息和庫存是否保持不變。
6. 新增自己的商品，修改價格，搜尋、篩選，並匯出 CSV。

Demo 模式關閉後會清空。若要保存自己的資料，改用 `sh ./mvnw spring-boot:run`，資料會存到本機 `data/` 資料夾。

## 建議閱讀順序

- `Product.java`：商品有哪些欄位？`@Entity`、`@Id` 和唯一 SKU 各代表什麼？
- `StockMovement.java`：為什麼要把變動記錄和商品分開？一個商品可以對應很多筆變動。
- `InventoryController.java`：HTTP 路徑如何對應 Java 方法？`GET`、`POST`、`PUT` 的用途有何不同？
- `InventoryService.java`：主要業務規則都在這裡。先看 `save()`，再看 `move()`，最後看統計和 CSV。
- `ProductRepository.java`：Spring Data JPA 提供資料存取；變動庫存前會鎖住該商品記錄。
- `InventoryTests.java`：測試如何驗證正常流程和失敗流程？
- `static/app.js`：頁面透過 `fetch()` 呼叫 API，再把結果顯示到畫面。

## 要能自己解釋的幾件事

**為什麼不用直接修改 quantity？**

因為每次數量變動都應該有方向、數量和原因。直接改數量會讓「為什麼剩這麼多」變得難以追查。

**為什麼需要 transaction？**

更新商品數量和新增變動記錄應該一起成功或一起失敗，不能只完成一半。

**如果兩個請求同時出庫呢？**

例如只剩 1 件，兩個請求各要取 1 件。如果都先讀到 1，就可能各自認為有貨。這裡用資料庫鎖，讓同一商品的兩次變動依序檢查最新庫存。

**為什麼價格用 BigDecimal？**

它適合精確處理十進位金額。這個項目只接受兩位小數，避免浮點數計算金額時的精度問題。

**這個項目的限制是什麼？**

只有單一使用者、單一工作區、歐元和本機資料庫；沒有登入、訂單、供應商或真正的會計功能。這讓範圍保持在個人練習可以理解和維護的程度。
